## 1. 컨테이너 구성

- **Frontend**: `nginx:1.27-alpine` 실행 이미지(빌드 `node:20.18-alpine`) — React 빌드 정적 서빙 + `/api/` 프록시 · **유일한 외부 공개(80)**
- **Backend**: `eclipse-temurin:17-jre-jammy` 실행 이미지(빌드 `maven:3.9.9-eclipse-temurin-17`) — Spring Boot API · SSE 중계 · Flyway
- **AI Module**: `python:3.12-slim` + uv — FastAPI · RAG · FAISS 인덱스 파일
- **Database**: `mariadb:10.11.10` — 데이터 volume `db-data`
- **Vector 인덱스**: FAISS 저장 경로 `/data/vector` → volume `vector-data`(AI 컨테이너에 마운트)

## 2. Docker 설정

### 2.1 Frontend Dockerfile

빌드 컨텍스트는 **리포 루트**(nginx 설정을 같이 넣는다 · compose `build.context: .`).
```dockerfile
FROM node:20.18-alpine AS build
WORKDIR /app
COPY frontend/package.json frontend/package-lock.json ./
RUN npm ci
COPY frontend/ ./
# 같은 출처(nginx 프록시) — "/api"를 넣으면 /api/api/… 가 된다 (Dockerfile은 줄 끝 주석을 허용하지 않는다 — 주석은 따로 줄에)
ENV VITE_API_URL=""
RUN npm run build

FROM nginx:1.27-alpine
COPY nginx/default.conf /etc/nginx/conf.d/default.conf
COPY --from=build /app/dist /usr/share/nginx/html
EXPOSE 80
```
nginx 공식 이미지는 HEALTHCHECK·USER를 두지 않는다(compose `depends_on`과 외부 포트 확인으로 대신).

### 2.2 Backend Dockerfile

```dockerfile
FROM maven:3.9.9-eclipse-temurin-17 AS build
WORKDIR /app
COPY pom.xml .
RUN mvn -B -q dependency:go-offline
COPY src ./src
RUN mvn -B -q package -DskipTests

FROM eclipse-temurin:17-jre-jammy
RUN apt-get update && apt-get install -y --no-install-recommends curl \
 && rm -rf /var/lib/apt/lists/* \
 && useradd --system --uid 1001 --create-home app
WORKDIR /app
COPY --from=build /app/target/*.jar app.jar
USER app
ENV TZ=Asia/Seoul JAVA_TOOL_OPTIONS="-Duser.timezone=Asia/Seoul"
EXPOSE 8080
HEALTHCHECK --interval=15s --timeout=10s --start-period=90s --retries=5 \
  CMD curl -fsS http://localhost:8080/actuator/health || exit 1
ENTRYPOINT ["java", "-jar", "/app/app.jar"]
```
멀티스테이지 · 실행 이미지 JRE · 비root(uid 1001) · `/actuator/health`는 SecurityConfig에서 인증 없이 허용(ADMIN 규칙보다 위).

### 2.3 AI Module Dockerfile

```dockerfile
FROM python:3.12-slim
COPY --from=ghcr.io/astral-sh/uv:0.11.32 /uv /uvx /bin/
ENV UV_COMPILE_BYTECODE=1 UV_LINK_MODE=copy UV_PYTHON_DOWNLOADS=0 \
    PYTHONDONTWRITEBYTECODE=1 PYTHONUNBUFFERED=1 TZ=Asia/Seoul
RUN useradd --system --uid 1001 --create-home app && mkdir -p /data/vector && chown app /data/vector
WORKDIR /app
COPY pyproject.toml uv.lock .python-version ./
RUN uv sync --locked --no-dev
COPY app ./app
ENV PATH="/app/.venv/bin:$PATH"
USER app
EXPOSE 8000
HEALTHCHECK --interval=15s --timeout=10s --start-period=30s --retries=5 \
  CMD python -c "import urllib.request;urllib.request.urlopen('http://localhost:8000/health', timeout=8)" || exit 1
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000", "--workers", "1"]
```
slim 이미지에는 curl이 없어 HEALTHCHECK는 python urllib · `/health`는 내부 토큰 예외 · uv는 버전 태그로 고정(`:latest` 금지) · `--locked`라 `uv.lock`이 `pyproject.toml`과 어긋나면 빌드가 멈춘다 · 워커 1(FAISS 인덱스는 프로세스 메모리).

## 3. Docker Compose

`docker-compose.yml` 요점:

| 항목 | 값 |
|---|---|
| 외부 포트 | `frontend` `80:80` **하나만** — backend·ai-service·database에는 `ports` 없음 |
| 네트워크 | `edge`(frontend·backend) · `app`(backend·ai-service — 일반 bridge, AI가 OpenAI·Tavily로 나가야 함) · `data`(backend·database — **`internal: true`**) |
| 기동 순서 | database·ai-service healthy → backend healthy → frontend (`depends_on: condition: service_healthy`) |
| volume | `db-data`(/var/lib/mysql) · `vector-data`(/data/vector) |
| 환경변수 | 서비스별 `environment:`에 **필요한 키만** — LLM 키는 ai-service에만, JWT·DB 계정은 backend에만 |
| 필수 값 | `${DB_PASSWORD:?…}`처럼 비어 있으면 compose가 기동을 거부한다(DB_NAME·DB_USER·DB_PASSWORD·DB_ROOT_PASSWORD·JWT_SECRET·AI_INTERNAL_TOKEN) |
| DB 옵션 | `utf8mb4` · `--default-time-zone=+09:00` · healthcheck `healthcheck.sh --connect --innodb_initialized` |

`docker-compose.dev.yml`(로컬 디버깅 전용): database `127.0.0.1:3306` · backend `127.0.0.1:8080` · ai-service `127.0.0.1:8000` — **127.0.0.1에만 바인드**(외부 노출 아님). 백엔드 테스트 DB·둘째 seam 검사에 쓴다.

```bash
cp .env.example .env                                   # 값 채우기
docker compose up -d --build                           # 운영 구성 → http://localhost
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d database   # 테스트용 DB만
docker compose ps && docker compose logs -f backend
```

## 4. 환경 변수

### 4.1 개발 환경

`.env.example`의 키(값 없음): `DB_NAME` · `DB_USER` · `DB_PASSWORD` · `DB_ROOT_PASSWORD` · `JWT_SECRET`(32바이트 이상) · `AI_INTERNAL_TOKEN` · `OPENAI_API_KEY` · `TAVILY_API_KEY` · `CORS_ALLOWED_ORIGINS` · `ACTUATOR_EXPOSURE`
프론트 로컬 개발: `frontend/.env.development`의 `VITE_API_URL=http://localhost:8080`(공개값 — 키 아님).

### 4.2 운영 환경

- EC2에서 `.env`를 **손으로 한 번** 만들고 `chmod 600 .env` — CI가 `echo`로 쓰지 않는다(Actions 로그·이력에 값이 남는 경로를 만들지 않기 위해).
- 키 이름은 4.1과 같다. `CORS_ALLOWED_ORIGINS`: 운영은 nginx 같은 출처라 CORS가 필요 없다(5번 명세 §5.3) — 값은 `http://<EC2 주소>`로 둬도 되고, **80이 아닌 외부 포트로 열 때만** 그 접속 주소가 반드시 있어야 한다(아래 nginx 경로 문단). `*`는 기동 거부.
- 비밀값 생성: `openssl rand -base64 48`(JWT) · `openssl rand -hex 32`(내부 토큰).

### 4.3 비밀정보 관리

- `.env` 는 `.gitignore` 에 등록, 저장소에는 `.env.example` (값 없는 샘플)만 커밋
- CI/CD 에서 사용하는 값은 GitHub Secrets 에 등록
- Kubernetes 사용 시: 민감하지 않은 설정은 ConfigMap, 민감 정보는 Secret

## 7. 네트워크

| 서비스 | 포트 | 외부 공개 | 소속 네트워크 |
|--------|------|-----------|---------------|
| Frontend | 80 (nginx) | O (`80:80`) | edge |
| Backend | 8080 | X | edge · app · data |
| AI Module | 8000 | X | app |
| Database | 3306 | X | data (`internal: true`) |

nginx 경로: `/` → SPA(`try_files $uri /index.html`) · `/api/` → `backend:8080` · `/api/analyses/stream` → 같은 백엔드 + `proxy_buffering off` · `proxy_read_timeout 310s`(타임아웃 사슬 WebClient 290s < Spring 300s < nginx 310s) · 업로드 `client_max_body_size 1m` · CSP 헤더 · 백엔드 주소는 Docker DNS(`resolver 127.0.0.11`)로 요청마다 다시 찾는다 ·
`index.html`은 `no-cache`(재배포 뒤 옛 해시 파일을 찾지 않게) · `/assets/`는 없으면 404(HTML을 JS로 돌려주지 않게).

**외부 포트를 80이 아닌 값으로 바꿀 때**(예 `8081:80`): nginx가 `X-Forwarded-Port`를 넘기지 않아 Spring이 포트를 80으로 보고,
같은 출처 POST(로그인 포함)를 다른 출처로 판정해 CORS 403(봉투 아님)을 낸다 → `.env`의 `CORS_ALLOWED_ORIGINS`에 실제 접속 주소(`http://<호스트>:8081`)를 더한다.
