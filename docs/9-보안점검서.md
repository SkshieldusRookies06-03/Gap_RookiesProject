## 7. 잔여 위험 및 향후 과제

| 항목 | 미조치 사유 | 완화 방안 / 향후 계획 |
|------|-------------|------------------------|
| Refresh Token을 localStorage에 보관 | 쿠키로 옮기면 CSRF 대책이 다시 필요(B-6 전제가 깨짐) | CSP · 텍스트 렌더(F-1) · Refresh 회전(재사용 시 401) · 로그아웃 시 폐기 / 향후 HttpOnly 쿠키 + CSRF 토큰 |
| 사용자당 로그인 1곳(Refresh를 users 컬럼에 저장) | 테이블 4개 상한(ADR-02) | 새 기기 로그인 시 이전 기기 Refresh 무효 — 보안상으론 안전한 쪽 / 향후 토큰 테이블 분리 |
| 계정 잠금을 악용한 타인 잠금(DoS) | 잠금이 Brute Force 대책의 전부 | 15분 자동 해제 · 존재하지 않는 이메일은 잠그지 않아 계정 존재가 드러나지 않음 / 향후 IP 기준 제한·CAPTCHA |
| 이름·주소·자유 서술 속 개인정보 미마스킹 | 정규식으로 판별 불가 | 업로드 화면 안내 문구 · 데모 데이터는 가짜 인물만 / 향후 NER 기반 마스킹 |
| Rate Limit 없음(A-4) | 6일 범위 밖 | 질문 1000자 · 청크·웹 결과 상한 / 향후 사용자별 분당 호출 제한 |
| 로그아웃 뒤 Access Token 최대 15분 유효 | `JwtAuthenticationFilter`가 매 요청 DB를 보지 않는다(무상태 JWT) | Access 15분으로 짧게 · 로그아웃 시 Refresh 폐기 / 향후 `token_version` 컬럼 비교 또는 차단 목록 |
| 시드 계정(kim/lee)이 운영 DB에도 적용 | Flyway 경로가 하나라 V2 시드가 EC2에도 들어간다 · 비밀번호(`Passw0rd!`)가 README에 공개 | 시연 직후 비밀번호 변경 또는 시연 전용 인스턴스 · 잠금 DoS는 15분 자동 해제 / 향후 시드를 `db/seed` 별도 경로 + `seed` 프로파일에서만 적용 |
| 정규식 밖 연락처 표기(괄호 지역번호·유선 번호 등) | 패턴 기반 마스킹의 한계 | 휴대폰은 하이픈·점·공백·+82 모두 처리(SPEC §6.5) / 향후 NER 기반 마스킹 |
