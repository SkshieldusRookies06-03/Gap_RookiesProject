# F-6 외부 입력 검증 — 업로드 확장자·크기 · 질문 길이 (클라이언트 / 서버 구분)
# 환경: 2026-11-09 KST · 1)·2)는 mock 8090 + Vite 5174 · headless Chrome / 3)은 Docker Compose(nginx → backend)
# 파일: ok.md(21B) · big.md(307,206B ≈ 300KB) · a.exe(7B) · a.txt.exe(이중 확장자 · 3)에서만)

## 1) 클라이언트 (frontend/src/hooks/useUpload.js — 요청 전에 막는다)
코드: /\.(md|txt)$/i 아니면 UNSUPPORTED_FILE · size 0이면 VALIDATION_ERROR · size > 200*1024면 FILE_TOO_LARGE · 제목 1~100자
파일 선택창 accept=".md,.txt" (선택 편의일 뿐 — 강제 아님)
화면 재현(내 문서 → 업로드):
  a.exe  → 문구 ".md 또는 .txt(UTF-8) 파일만 올릴 수 있습니다" · POST /api/documents 요청 0건
  big.md → 문구 "200KB 이하 파일만 올릴 수 있습니다"            · POST /api/documents 요청 0건
질문: 후속 질문 textarea maxlength=1000 (/analyses/7에서 확인)

## 2) 서버 — 목(mock/server.mjs) 기준: 클라이언트를 거치지 않고 curl로 직접
$ curl -s -X POST localhost:8090/api/documents -H "Authorization: Bearer $T" -F file=@a.exe -F type=RESUME -F title=…
415 UNSUPPORTED_FILE
$ (같은 명령, file=@big.md)
413 FILE_TOO_LARGE
$ curl -s -X POST localhost:8090/api/analyses/stream -H "Authorization: Bearer $T" -H 'Content-Type: application/json' -d '{"analysisId":"7","question":"가"×1001}'
400 VALIDATION_ERROR
→ 클라이언트 검사를 건너뛰어도(우회) 서버가 다시 막는다 — 단 이건 목 서버다(실제 백엔드는 3)

## 3) 실제 백엔드 — Docker Compose 검증 (사용자 직접 실행 · 결과 보고 기준)
검증일: 2026-11-09 KST
환경: Docker Compose (nginx → backend)
요청: POST http://localhost/api/documents (클라이언트 검사를 거치지 않고 직접)
인증: 정상 accessToken 사용 (실제 토큰 값은 기록하지 않음)

### 정적 코드 확인
backend/.../document/DocumentService.java:138  확장자 .md/.txt + ALLOWED_MIME 아니면 UNSUPPORTED_FILE
                                         :141  file.getSize() > 200KB → FILE_TOO_LARGE
                                         :145  UTF-8 엄격 디코딩(CodingErrorAction.REPORT) 실패 → UNSUPPORTED_FILE
nginx/default.conf client_max_body_size 1m (1MB 초과는 nginx 413 — 프론트 client.js가 비봉투 413을 FILE_TOO_LARGE로 바꿈)

### 실제 서버 업로드 테스트
| 테스트 파일 | 기대 결과 | 실제 결과 | 판정 |
|---|---|---|---|
| a.exe (7B) | 415 UNSUPPORTED_FILE | 415 UNSUPPORTED_FILE | PASS |
| big.md (307,206B) | 413 FILE_TOO_LARGE | 413 FILE_TOO_LARGE | PASS |
| a.txt.exe (이중 확장자) | 415 UNSUPPORTED_FILE | 415 UNSUPPORTED_FILE | PASS |

### 실제 서버에서 하지 않은 것 (미검증)
- 1MB 초과 업로드 → nginx 413 (→ B-10 · T-063)
- 질문 1001자 → 400 VALIDATION_ERROR (실제 백엔드로는 미실행 · 목 2)만)

## 최종 결과
- 클라이언트: 허용 밖 확장자·200KB 초과는 요청 전에 안내 · 요청 0건 → PASS
- 목 서버: 415 · 413 · 400 → PASS
- 실제 백엔드: 프론트 검사를 우회한 직접 요청에서도 허용 밖 확장자·크기 초과·이중 확장자를 모두 거부 → PASS

**판정: PASS** (위 3가지 업로드 사례 기준)

단, 모든 파일 형식·인코딩·경계값을 검증한 것은 아니며, nginx 1MB 413과 실제 백엔드 질문 1001자는 미검증이다.
